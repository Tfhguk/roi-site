# Учёт техники и ArUco

Кнопка **«3D симуляция»** открывает MuJoCo прямо на сайте: WebAssembly рассчитывает физику в отдельном потоке, Three.js рисует сцену через WebGL. Python и отдельный сервер пользователю не нужны. Локальный запуск также доступен через `start-mujoco.cmd`. Инструкция и ограничения физической модели: [mujoco_sim/README.md](mujoco_sim/README.md).

## Регистрация, полигоны и личная техника

У пользователя может быть несколько проектов полигонов. У каждого сохраняются собственные гараж, зоны, глубины, траектории и этап настройки. Список «Мои проекты» позволяет открыть нужный гараж; переключение и обновление страницы восстанавливают личные правки. ID 0–49 независимы между полигонами: одинаковый ID разрешён на разных площадках, а внутри одной граница, техника и зоны разных пользователей не получают дубликатов. Экспорт JSON и PDF относится только к выбранному полигону.

«Показать полный полигон» в выборе площадки или редакторе границы открывает отдельный просмотр границы, всех сохранённых зон и их меток. Поле целиком помещается в окно, внизу показаны цвета типов зон. Просмотр не меняет активный проект и закрывается кнопкой или Escape.

«Удалить гараж» доступно в списке проектов и внутри гаража. После подтверждения удаляются только ваша техника и её траектории выбранного полигона, освобождаются ID техники и гараж убирается из личного списка. Зоны, глубины, общий пресет и чужая техника сохраняются. Повторный выбор полигона открывает пустой гараж с сохранёнными зонами.

При загрузке оригинала личные зоны заменяются целиком: их старые ID освобождаются до назначения новых, свободные ID выбираются по возрастанию. ID техники сохраняются. При перезагрузке собственного пресета его исходные метки остаются зарезервированными; повторные загрузки не накапливают и не теряют ID.

Владелец изменяет границу и зоны своего пресета кнопкой «Сохранить на сервере». Если версия оригинала изменилась, при следующем открытии чужого проекта загружаются новые зоны и сбрасываются траектории; гараж и глубины сохраняются. Кнопка «Загрузить оригинал заново» позволяет явно заменить личные зоны пресетом. Чужой оригинал нельзя изменить или удалить. «Удалить мой пресет» убирает его из общего выбора, сохраняя уже загруженные проекты и технику пользователей. Для действующей базы выполните [polygon-presets.sql](supabase/polygon-presets.sql); эта миграция также включена в полную схему и `transport-migration.sql`.

На экранах от 1100×600 редактор использует боковую навигацию: справа постоянно видны этапы, обучение, меню «Скачать», сохранение и переход далее. Название полигона и выбор основы находятся над полем, подсказки и инструменты рисования — слева. Кнопка «К списку полигонов» закрывает редактор без потери текущего рисунка. На небольших экранах навигация остаётся сверху, а инструменты размещаются компактно. PDF меток и JSON проекта доступны через общее меню «Скачать».

В проекте полигона допускается одна транспортная зона. Повторное добавление блокируется в редакторе и серверной операцией сохранения. Её можно изменять и удалять; старые проекты с несколькими такими зонами требуют удаления лишних перед следующим сохранением. Личные зоны разных аккаунтов остаются независимыми.

Правая кнопка мыши на карте открывает меню завершения фигуры: для нового полигона — «Замкнуть фигуру», для зоны — «Замкнуть и завершить фигуру». Зона проверяется и добавляется в проект; на сервер её сохраняет обычная кнопка сохранения. Владелец общего полигона может изменить его название в поле редактора и нажать «Сохранить название». Геометрия и ID при переименовании сохраняются; сервер отклоняет изменения имени другими пользователями. Для существующей базы обновите `transport-migration.sql` (операция `rename_polygon`).

Раздел «Траектории» временно отключён: карточка на главной и кнопка в навигации неактивны, после сохранения зон открывается главная. Код, статусы и сохранённые маршруты остаются в проекте. Для возобновления используется флаг `ROI_CLOUD.features.routes = true` в публичной конфигурации.

Каждый этап содержит краткую последовательность действий; редактор дополнительно подсказывает следующий шаг. Гараж позволяет выбирать и менять ID от 0 до 49. Сервер проверяет общие резервации всего полигона, включая границы, зоны и технику других пользователей. После смены ID нужно заново скачать и распечатать метку. Для существующей базы примените обновлённый `supabase/transport-migration.sql`: он добавляет `create_equipment_with_id` и `set_equipment_marker` с проверкой владельца и блокировкой полигона на время изменения.

Во время регистрации каждый этап автоматически открывает окно обучения с текстом и анимацией. Подтверждение сохраняется в `profiles.tutorial_seen` через `mark_stage_tutorial`; оно действует для аккаунта на всех устройствах и не меняет статус регистрации. После подтверждения окно повторно открывается только вручную кнопкой «Обучение» снизу. Отключённые этапы автоматически не показывают обучение; для аккаунтов с завершённой регистрацией оно доступно вручную. Для существующей базы обновите `transport-migration.sql`. При включённом уменьшении движения анимации заменяются неподвижной схемой.

Главная и активные этапы настройки помещаются в экран. Длинные списки техники, зон и вершин переключаются страницами. В редакторе зон карта занимает всю ширину; выбор зоны находится сверху, имя и сохранение фигуры — снизу. Списки открываются отдельной панелью без уменьшения карты.

Новый серверный режим: регистрация → создание/выбор общего полигона → личный гараж и ArUCo → четыре типа зон → редактируемые траектории с псевдокартой глубины. Редактор открывается в `setup.html`, работает на пустом поле и умеет переключаться на камеру. Общие полигоны и данные аккаунта сохраняются в Supabase.

При первом переходе к траекториям создаётся тестовая карта глубины и строятся пути между зонами. Кнопка «Построить автоматически» пересчитывает пути по текущей карте с ограничениями глубины и перепада. В разделе «Карта глубины и автопостроение» можно сгенерировать новый тестовый рельеф, выбрать технику и ограничения, скачать или загрузить JSON. Готовые пути редактируются вручную и сохраняются вместе с картой в Supabase.

Транспортная зона задаёт разрешённую область движения. Склад, добыча и зарядка должны целиком находиться в ней. Маршруты соединяют добычу со складом и склад с зарядкой, проходят только по транспортной зоне и предпочитают минимальные перепады короткому пути через крутой рельеф. Новые тестовые карты сохраняют проходы ко всем рабочим зонам. Карта занимает всю доступную площадь окна; настройки и список траекторий открываются поверх неё и не уменьшают поле. Для обновления существующей базы предусмотрен [transport-migration.sql](supabase/transport-migration.sql).

Подключение базы, SQL-схема и описание редактора: [supabase/README.md](supabase/README.md). Без публичных параметров Supabase сохраняется прежний локальный демо-режим. Для проверки серверного сценария: `npm.cmd run build`, затем `npm.cmd run test:setup`.

Траектории сгруппированы в карточках по имени техники. Наведение показывает точки её путей; нажатие закрепляет выделение. Под именем машины у каждого маршрута есть кнопки «Изменить» и «Удалить». На карте нет номеров маршрутов и подписей их точек. Автопостроение и проверка отредактированных путей учитывают отступы от внешних границ транспортной области и от центров арукомаркеров полигона/зон. По умолчанию это 5 и 40 единиц поля 1000×700; в настройках задайте расстояния с учётом габаритов техники и запаса. Когда безопасного прохода нет, предыдущие маршруты сохраняются и выводится сообщение.

Карточки техники доступны на поле и в панели свойств; выбор работает также с клавиатуры и на сенсорном экране. Типы гаража: самосвал, бульдозер, погрузчик, зарядная станция и иное. Только самосвал получает перевозки добыча ↔ склад. Бульдозер работает на складе, погрузчик — в зоне добычи; автоматически им создаются только поездки со своей базы на зарядку и обратно. Самосвал ездит на зарядку со склада. Зарядная станция неподвижна, тип «Иное» не получает автоматических заданий; его маршруты можно задать вручную без назначения перевозки самосвала. Миграция заменяет `excavator` на `bulldozer`, а `robot` на `charging_station`, сохраняя ID, метки и пользовательские названия. Новые станции оформлены фиолетовым, «Иное» — розовым.

## GitHub Pages

Репозиторий проекта: https://github.com/Tfhguk/roi-site. После включения Pages сайт будет доступен по адресу https://tfhguk.github.io/roi-site/. Workflow публикует обновления ветки `main`; относительные пути страниц и Worker поддерживают имя репозитория `roi-site`.

Текущая версия работает на GitHub Pages: HTML, JavaScript, PDF и распознавание выполняются в браузере. GitHub Pages выдаёт HTTPS-адрес `https://ЛОГИН.github.io/roi-site/`. Отдельный постоянно работающий Node.js-процесс для этих функций не требуется. Pages не запускает `server.cjs` или Python и не предоставляет общую базу пользователей. Источник: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages.

1. Создайте публичный репозиторий `roi-site` на https://github.com/new (для текущего проекта он уже создан). Для бесплатного GitHub Pages репозиторий должен быть публичным.
2. Загрузите исходники в ветку `main`, сохранив `.github/workflows/pages.yml`, `package.json`, `package-lock.json` и `build.cjs`. Если файлов ещё нет в репозитории, загрузите исходные файлы через **Add file → Upload files**. Проверьте, что `.github/workflows/pages.yml` тоже загружен. Каталоги зависимостей, результаты тестов и готовую сборку загружать в репозиторий не нужно.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
4. Откройте **Actions → Publish GitHub Pages → Run workflow**, выберите `main` и запустите публикацию. В дальнейшем она запускается после каждого обновления `main`.
5. После успешного завершения адрес сайта появится в **Settings → Pages** и в окружении **github-pages**. При наличии переключателя включите **Enforce HTTPS**.

Workflow устанавливает зависимости через `npm ci`, запускает `npm run build`, проверяет новую регистрацию и PostgreSQL-политики через `npm run test:setup` и публикует только `dist/`. Каталоги `.lan-tls/`, `node_modules/`, тестовые результаты и архивы исключены из Git. Не загружайте всю рабочую папку через браузер: такой способ не учитывает `.gitignore`.

Проверка страниц, PDF и распознавания с камерой в подпапке, как на GitHub Pages:

```powershell
npm.cmd run build
npm.cmd run test:pages
```

## Бесплатный хостинг

Сборка для публикации:

```powershell
npm.cmd install
npm.cmd run build
```

Готовый сайт находится в `dist/`, архив — `aruco-site.zip`. В сборку входят страницы, распознавание и PDF-библиотека. Локальные сертификаты, ключи и служебные файлы в неё не включаются.

Откройте https://app.netlify.com/drop и загрузите папку `dist` или архив `aruco-site.zip`. Netlify выдаст адрес с HTTPS вида `https://имя.netlify.app/`. Для постоянного управления сайтом зарегистрируйтесь на бесплатном тарифе и закрепите проект за своим аккаунтом кнопкой **Claim this site**. Публикация без входа защищена временным паролем и, по сообщению интерфейса Netlify Drop при проверке, истекает через час без закрепления. Если после входа проект имеет видимость Private, переключите его в Public для доступа других пользователей. Подробности: https://docs.netlify.com/start/quickstarts/netlify-drop-quickstart/.

На хостинге сайт работает при выключенном компьютере владельца. Камера используется на устройстве посетителя после его разрешения. Пользователи, маркеры и настройки по-прежнему хранятся в браузере каждого устройства; общей базы между компьютерами пока нет. Встроенный вход предназначен для демонстрации и не защищает файлы опубликованного сайта.

После изменений повторите сборку и загрузите обновлённую папку `dist` в существующий проект Netlify. Для проверки именно публикуемых файлов выполните `npm.cmd run test:hosting` после сборки.

## Локальный запуск

Запуск из папки проекта:

```powershell
npm.cmd install
python -m pip install -r requirements.txt
npm.cmd start
```

Откройте https://localhost:8443/ (или http://localhost:8000/login.html на самом компьютере). С подключённым Supabase зарегистрируйте серверный аккаунт и входите по email и паролю. Демо-вход `admin` / `admin123` доступен только при пустых параметрах `cloud-config.js`.
Для уже подготовленного проекта достаточно `npm.cmd start` (в PowerShell). Серверный аккаунт проходит этапы полигона, гаража, зон и траекторий. В прежнем демо-режиме остаются два раздела: создание маркеров и поиск границы по камере.

## Подключение по локальной сети

`npm.cmd start` запускает сервер на всех IPv4-интерфейсах (`0.0.0.0`): HTTPS на **8443**, HTTP на **8000**. Вместо команды можно открыть `start-lan.cmd`. Компьютер должен оставаться включённым, а процесс сервера — работающим.

При запуске сервер выводит адреса: например, `https://192.168.0.120:8443/` и `https://192.168.4.134:8443/`. На телефоне или другом компьютере в той же сети откройте адрес соответствующего Wi-Fi-интерфейса. VPN и виртуальные адаптеры выводятся ниже; обычно для подключения телефона нужен адрес Wi-Fi.

Вход (`crypto.subtle`) и камера требуют защищённого соединения при обращении по IP. Поэтому HTTP-запросы из локальной сети автоматически переводятся на HTTPS. На этом компьютере прежний HTTP-адрес localhost продолжает работать. Видеопоток берётся с камеры устройства, на котором открыта страница.

При первом запуске создаётся локальный самоподписанный сертификат в `.lan-tls/`. При первом открытии собственного HTTPS-адреса браузер покажет предупреждение: откройте «Дополнительно» и подтвердите переход к своему локальному серверу, затем разрешите доступ к камере. Если браузер устройства требует доверенного сертификата, его нужно установить в доверенные сертификаты этого устройства или использовать сертификат, выданный доверенным локальным центром. Сам сервер не изменяет хранилища доверенных сертификатов. В консоли выводится SHA-256 отпечаток сертификата. При изменении IP или истечении срока сертификат автоматически обновляется.

Если доступ блокирует брандмауэр Windows, выполните **PowerShell от имени администратора** в папке проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\enable-lan.ps1
```

Скрипт добавляет правило только для Node.js, портов 8443/8000, активных физических сетевых адаптеров и устройств локальной подсети. Проброс портов на роутере не нужен.

Для другого HTTPS-порта:

```powershell
npm.cmd start -- --port 9443 --http-port 9000
```

Соответствующее правило брандмауэра: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\enable-lan.ps1 -Port 9443 -HttpPort 9000`. Только HTTPS: `npm.cmd start -- --port 9443 --no-http`. Привязка к одному адресу: `--host 192.168.0.120`. Остановка сервера — Ctrl+C.

Корень `/` открывает страницу входа. Каталоги, ключ сертификата, настройки и серверные файлы через сайт не выдаются. Правило брандмауэра можно удалить командой администратора `Remove-NetFirewallRule -Name EquipmentArUcoLAN-8443-8000`.

Пользователи и маркеры остаются в хранилище каждого браузера: при переходе на другой адрес/порт или подключении другого устройства данные автоматически не переносятся и не синхронизируются.

## Маркеры

По умолчанию создаются **OpenCV DICT_4X4_50**, ID **0–49**. В программе распознавания нужно выбрать этот же словарь. ID в интерфейсе и OpenCV совпадают: смещения на 1 нет.

В редакторе также доступен **ArUco Original 5×5**, ID **0–1023**. Старые записи без поля `dictionary` относятся к этому формату: их ID и рисунок сохраняются. Для детектора OpenCV это `DICT_ARUCO_ORIGINAL`.

Превью, SVG и PDF строятся из одной матрицы. Белое поле вокруг маркера необходимо сохранить при обрезке и печати. На листе A4 размещаются 2 маркера в ряд и 3 ряда (6 маркеров на страницу); размер изображения с белым полем — примерно 89 мм. PDF содержит векторные ячейки и подпись словаря/ID; при печати используйте масштаб 100%.

Генерация и PDF используют локальные файлы, интернет после установки зависимостей не требуется. Если отсутствует jsPDF, выполните `npm install`.

Для пересоздания словаря и PNG-превью:

```powershell
npm run generate
```

Результаты сохраняются рядом с `generate_dict.py`, даже при запуске из другой папки. Для обычной работы сайта Python-генератор запускать не нужно: JS-словарь уже включён.

## Проверка

```powershell
npm test
npm run test:browser
npm run test:polygon
npm run test:server
```

Первая команда сравнивает все 50 маркеров JavaScript и SVG с OpenCV, распознаёт каждый в четырёх поворотах, проверяет 1024 старых маркера и PNG-превью. Дополнительно проверяются синтаксис страниц, локальные скрипты, диапазоны ID и повреждённые сессии.

Браузерная проверка использует установленный Microsoft Edge. Для установленного Chrome задайте `$env:TEST_BROWSER_CHANNEL="chrome"`. Результаты скачивания и снимки экрана сохраняются в `test-output/`. OpenCV также проверяет реальные снимки превью и слой ячеек в экспортированных PDF (включая смешанные словари). Тесты используют отдельный временный профиль и не меняют данные основного браузера.

Проверка сервера запускает HTTPS на свободных временных портах, проверяет обращение по локальному IP, перенаправление HTTP, доступность страниц и ограничение выдачи файлов, вход, камеру и Worker через HTTPS. Предупреждение о сертификате принимается только в тестовом профиле. Физическая камера не используется.

## Границы полигона с камеры

Перейдите из `welcome.html` в **«Границы полигона»** (`polygon.html`).

1. Нажмите **«Включить камеру»** и разрешите доступ в браузере. По умолчанию запрашивается задняя камера; другую можно выбрать в настройках.
2. Наведите камеру так, чтобы арукомаркеры границы были видны в одном кадре. Первый клик рядом с арукомаркером фиксирует изображение. Также можно заранее нажать **«Зафиксировать кадр»**.
3. Нажимайте рядом с арукомаркерами в порядке обхода границы. Детектор ищет ближайший арукомаркер в указанном радиусе. Вершина ставится в пересечение его диагоналей: при перспективном искажении это проекция центра маркера. Если маркер не распознан, вершина не добавляется.
4. После выбора минимум трёх вершин нажмите **«Замкнуть полигон»** или повторно выберите первый арукомаркер. Самопересекающуюся и вырожденную границу завершить нельзя. Пунктир до замыкания показывает предварительное последнее ребро.
5. Если при замыкании появляется пересечение (например, выбраны верхняя левая, верхняя правая, нижняя левая и нижняя правая арукомаркеры), нажмите **«Исправить порядок»**. Программа переставит вершины, сохранив все выбранные арукомаркеры, их координаты и первую вершину. Затем замкните границу. Корректный порядок, включая вогнутую границу, остаётся без изменений; вырожденную границу из точек на одной прямой исправить нельзя.
6. Стрелками **↑ / ↓** у вершин можно вручную менять порядок обхода. **«Отменить»** возвращает предыдущее состояние после добавления, удаления, перестановки, автоматического исправления или очистки (до 100 действий в текущем кадре). Самопересекающийся предварительный контур выделяется оранжевым; его сохранить нельзя.
7. Сохраните **кадр с полигоном в PNG** или **координаты в JSON**. Можно удалить отдельную вершину, очистить границу или вернуться к редактированию. Новый кадр и смена словаря начинают отдельную историю изменений.

Координаты относятся к исходному зафиксированному кадру (в пикселях, начало — левый верхний угол), а не к размеру изображения на экране. JSON содержит размер кадра, словарь, ID, центры и углы маркеров. Это граница на изображении; расстояния в метрах и географические координаты не вычисляются.

**«Новый кадр»** возвращает прямой эфир и очищает текущую границу после подтверждения. Выключение камеры сохраняет уже зафиксированный кадр для дальнейшей разметки. При выходе со страницы видеопоток останавливается.

В настройках выбираются `DICT_4X4_50` или `ARUCO_ORIGINAL` и радиус поиска. Распознавание выполняется локально через установленный `js-aruco2`; видеокадры не отправляются на сервер. Через HTTP/HTTPS поиск работает в Web Worker. При открытии HTML двойным щелчком (`file://`) или блокировке Worker поиск автоматически выполняется на самой странице. После `npm.cmd install` интернет для работы не нужен. Рекомендуемый запуск камеры — `http://localhost:8000` или HTTPS: для локальных файлов разрешения камеры и общее хранилище страниц зависят от браузера, а при открытии сайта по обычному HTTP с другого устройства камера может быть недоступна.

`npm.cmd run test:polygon` проверяет оба словаря и четыре поворота (220 распознаваний), геометрию, а затем весь сценарий в Edge с синтетическим видеопотоком. Проверяются поиск по клику, центры при перспективе, порядок вершин, замыкание, самопересечения, отмена/удаление, координаты после изменения размера окна, PNG/JSON, остановка потока и отказ в доступе к камере. Физическая камера для теста не используется. Примеры результата: `test-output/polygon.png` и `test-output/polygon.json`.

## Тестовая симуляция зарядной станции

Кнопка **«Симуляция зарядной станции»** на главном экране открывает `charging.html`. Симуляция работает в браузере без подключения к оборудованию и без изменения серверных данных. Доступны запуск, пауза, остановка с возвратом механизма, сброс, изменение параметров и выгрузка результатов в `charging-test.json`.

Цикл: поиск нуля → обнаружение машины → совмещение → стыковка → зарядка CC/CV → отключение → расстыковка → возврат. В параметрах можно проверить отсутствие подтверждения контакта, потерю связи во время зарядки и положение контакта вне рабочей области. Ошибки показываются всплывающим уведомлением. После открытия параметров, обучения или ухода с вкладки расчёт остаётся на паузе до нажатия «Продолжить».

Все значения вымышленные: батарея 1S, 0,8 А·ч, начальный SOC 35 %, цель 95 %, ток CC 1 А, ограничение выхода 4,2 В; сопротивление проводки и контактов 0,12 Ом. Батарея использует синтетическую зависимость OCV(SOC), R0 = 0,1 Ом и одно RC-звено (Rp = 0,06 Ом, Cp = 600 Ф); температура фиксирована на 25 °C. Механика — идеальные оси с ограниченными скоростями и ускорениями, масса каретки 0,25 кг и жёсткость контакта 1000 Н/м. Полная динамика двигателей, CAD-геометрия, камера и реальные датчики пока не подключены. Основа аккумуляторной части: [эквивалентная схема батареи](https://www.mathworks.com/help/simscape-battery/ref/batteryequivalentcircuit.html).

В демонстрации механика воспроизводится ×1, зарядка ×120; в быстром режиме ×3 и ×600; в реальном времени всё ×1. На экране показаны модельное время, расчётные значения и текущий коэффициент воспроизведения. Экспорт содержит параметры, допущения, этапы и временные отсчёты с признаком `synthetic: true`.

Проверка после сборки: `npm.cmd run test:charging`. Тест проверяет CC/CV, последовательность этапов, запрет тока до стыковки и после ошибки, остановку, ограничения перемещений, управление в браузере, JSON и размещение без прокрутки на пяти размерах экрана.

## Учётные записи

Это локальное демоприложение: пользователи, хеши паролей, сессия, маркеры и выбор хранятся в `localStorage` браузера. Проверка сессий защищает от повреждённых записей, но для реального разграничения доступа нужна серверная авторизация. При смене адреса/порта или браузера будет отдельное хранилище.

Справочник словарей и формат маркеров: [OpenCV ArUco](https://docs.opencv.org/4.13.0/d5/dae/tutorial_aruco_detection.html).

## Тестовая симуляция самосвала

Кнопка **«3D симуляция»** открывает `truck.html`. Сначала доступен демонстрационный полигон с воспроизводимой картой глубины и путями. После входа можно выбрать свой проект, нажать «Загрузить», выбрать самосвал из его личного гаража и сохранённую траекторию этого самосвала. Загрузка не переключает активный полигон аккаунта. Чужая техника и пути другого полигона не подмешиваются. Если путей нет, «Построить тестовые пути» использует текущие зоны и глубины; результат существует только в памяти этой страницы. Временно выключенный этап «Траектории» остаётся выключенным.

Перед запуском проверяются границы, транспортная зона, высоты и отступы от арукомаркеров. Недоступные пути блокируются без подстановки прямой линии. В 3D контроллер ведёт физическое шасси MuJoCo вдоль запланированного пути; поле высот и контакты рассчитываются в метрах. Номинальный перепад по умолчанию 0,75 м, фактические высоты демонстрации примерно 0,11–0,64 м; в параметрах можно задать до 1,5 м и уклон до 25°. Рабочие площадки выровнены. Цвета пола показывают высоту, отдельные показатели — высоту поверхности и наклон шасси. Физика гусениц приближённая: опорные сферы и стабилизаторы наклона, без отдельных траков и калибровки устойчивости.

Камера вращается перетаскиванием в инвертированном направлении, колесо меняет масштаб. Правый клик и перетаскивание не вызывают меню и выделение браузера. Камера работает локально через GPU, физика — в Worker; граф маршрутов, скомпилированная модель и сцена повторно используются. Кнопка сброса возвращает машину в начало, сохраняя подготовленную сцену. Старая 2D версия доступна по `truck.html?view=2d`; её условная карта глубины и идеальная кинематика сохранены для сравнения.

В браузерной 3D версии при застревании самосвал пытается отъехать назад и перестроить маршрут. После двух неудачных попыток запрашивается ручное управление. Стрелки/WASD и экранные кнопки работают при ×1; отпускание, потеря фокуса и отсутствие обновления команды отключают тягу и включают торможение трением. При этом нет удержания координат, направления или компенсации тяжести: если сцепления недостаточно, машина скатывается. Ручное управление не ограничивается уклонами, клетками глубины и запомненными проблемными участками; программно сохраняется только внешняя граница полигона. Перепады и запреты карты не превращаются в физические стены: красные отметки рисуются по поверхности, контакты рассчитываются с рельефом и корпусом станции. «Вернуться к маршруту» продолжает рейс от текущего положения, сохраняя груз и заряд. На зарядке и с поднятым кузовом движение запрещено.

Успешно пройденные пути и проблемные участки сохраняются в этом браузере отдельно для аккаунта, полигона, машины, настроек и версии физики. Обычный «Сброс» не стирает опыт; в окне «Проходимость и память» есть отдельная очистка. Путь перед повторным использованием заново проверяется. Автопилот сначала ищет путь до 18°, затем обычный проезд до 25° с запасом тяги. Если обоих нет, снимает ограничение уклона и разрешает попытку проезда с предупреждением, даже при расчётном дефиците тяги. Это не гарантирует подъём: тяга в физике ограничена сцеплением и приводом, а при застревании срабатывают попытки выезда и запрос оператора. Границы, габарит, препятствия и сохранённые запреты не отменяются. Память локальная и не меняет пресет в Supabase. Проверки: `node test_learning.cjs`, `node test_recovery.cjs`, `node test_traction.cjs`.

Опорные сферы имитируют гусеницы: при движении используется сопротивление качению 0,03, при отпускании ручных кнопок — полный коэффициент трения поверхности (по умолчанию 0,5). Боковое сцепление и тяга ограничены нормальной нагрузкой на склоне и параметрами приводов. Это приближённая модель, без отдельных траков. Старый опыт от версии с почти нулевым трением не переносится на новую физику.

Рабочий цикл повторяется до команды остановки или неисправности. Погрузка занимает 4 модельные секунды. Разгрузка целиком занимает 4 секунды: 1 с подъём, 2 с выгрузка, 1 с опускание. Движения с поднятым кузовом нет. Счётчик показывает завершённые разгрузки. История этапов и отсчёты ограничены по объёму для длительной работы.

В браузерной 3D симуляции панель «Команды» показывает последние указания: движение вперёд и назад в метрах, повороты влево и вправо в градусах, остановки и рабочие операции. «Весь лог» открывает историю со страницами без прокрутки. Числа автопилота — задание на текущий участок, а не подтверждение его выполнения. При ручном управлении показывается фактически выполненное движение; удержание кнопки обновляет одну запись. Последние 200 записей с модельным временем включаются в `commandLog` скачиваемого расчёта, обычный сброс очищает журнал. Проверка: `node test_commands.cjs`.

В каждой подходящей зоне зарядки устанавливается неподвижная тестовая станция. Подтверждённых габаритов основания в предоставленной модели станции нет: размер 300×200 мм принят условно и подписан как тестовый. Его можно изменить в параметрах; геометрия всегда переводится в масштаб карты и не растягивается под зону. Корпус с зазором 20 мм учитывается как препятствие при построении путей; место установки выбирается внутри зоны, вне арукомаркеров и существующих траекторий. Если станция не помещается или нет допустимого подъезда, она не переносится за границу автоматически. Выдвижение и поворот контакта на карте берутся из координат существующей модели станции.

При достижении порога заряда (по умолчанию 25 %) либо оценочного резерва на доезд машина тормозит, после чего `truck-navigation.js` строит кратчайший допустимый путь из фактической точки остановки к станции. Для планирования используются карта высот, ограничения перепадов, границы, транспортная зона, отступы от меток и корпуса станций. Если прямая безопасна, выбирается она, включая проезд по допустимым склонам. В остальных случаях A* ищет обход минимальной длины по сетке с диагональными переходами и сокращением видимых участков. Среди достижимых с резервом заряда станций выбирается путь минимальной длины. Рабочие маршруты сохраняют прежний приоритет плавности рельефа. Оценка энергозатрат не гарантирует дальность реального робота; при отсутствии достижимого пути симуляция останавливается с уведомлением.

После подтверждения остановки и ориентации запускается существующая модель станции. `ChargingModel.Simulation` принимает общий объект батареи: SOC и RC-поляризация принадлежат одному объекту, ток потребителей вычитается из тока станции. Пока станция подключена, ход заблокирован; команда остановки сначала отключает ток и завершает расстыковку. После зарядки строится новый путь непосредственно к нужной рабочей зоне: с грузом на склад, без груза на добычу. Возвращения к точке прерывания нет. При прибытии самосвал присоединяется к сохранённому пути добыча–склад, если подходит его конец; иначе рабочее соединение строится по карте глубины. Отдельная страница станции сохраняет прежний режим работы.

Все численные параметры самосвала условные. Начальный масштаб — 0,01 м на единицу карты; его можно изменить вместе со скоростью, массой, грузом, ёмкостью и зарядом. Виртуальное питание: батарея 1S и шина приводов 12 В через преобразователь с КПД 0,85. Колея 0,11 м, продвижение 0,018 м/рад, предел вала 2π рад/с и момент 0,18 Н·м заданы для демонстрации, а не как идентифицированные характеристики установленного JGA25-370. Геометрия рычагов, калибровка сервы, реальная батарея/BMS, тепловые пределы, прочность и устойчивость остаются неизвестными. Подключения к оборудованию нет.

Скорость воспроизведения ×1/5/20/60 одинакова для самосвала и станции. Пауза и уход с вкладки останавливают модельное время; смена маршрута или параметров начинает новый опыт. `truck-test.json` версии 2 содержит выбранный проект, технику, исходный и активный маршруты, геометрию станций, историю выездов на зарядку, допущения, временные отсчёты и результат с `synthetic: true`. Проекты в базе не изменяются. Для изолированных численных проверок доступен одноразовый режим `route.continuous=false`; интерфейс всегда запускает непрерывную работу. Проверка: `npm.cmd run test:truck`.
