# 3D симуляция MuJoCo

На сайте кнопка **«3D симуляция»** открывает `truck.html`: официальный MuJoCo WebAssembly рассчитывает физику в Web Worker, Three.js рисует интерактивную сцену через WebGL. Это работает непосредственно на GitHub Pages, без Python и собственного сервера. Первая загрузка включает примерно 11 МБ WASM до сжатия. Выбор проекта, техники, маршрута, параметры, телеметрия и экспорт используют существующий интерфейс; исходные проекты в базе не меняются.

Локальный запуск из корня проекта: **`start-mujoco.cmd`**, адрес `http://127.0.0.1:8766/truck.html`. Лаунчер также подготавливает Python-окружение для дополнительного нативного режима; нужны Python 3.10+ и Node.js в PATH. Старый режим с Python API и потоком изображений доступен явно по `truck.html?mujoco=1`, а 2D версия — по `truck.html?view=2d`. Для обычной работы на сайте эти режимы не нужны.

Граф маршрутов готовится один раз; сброс с теми же параметрами переиспользует скомпилированную модель и GPU-сцену. Физика передаёт только преобразования движущихся объектов, статичные препятствия рисуются одним набором экземпляров. Камера вращается сразу в браузере, без сетевых запросов; неизменившаяся сцена не перерисовывается.

«Сброс» возвращает машину к началу выбранной траектории внутри полигона, обнуляет время, груз, рейсы и восстанавливает начальный заряд. Начальная позиция хранится в положении тела шасси, а координаты его скользящих суставов — как относительные смещения. Поэтому стандартный сброс MuJoCo тоже сохраняет машину внутри полигона. Ответы от старого расчёта после сброса не применяются к новому.

```powershell
.\start-mujoco.cmd
.\start-mujoco.cmd --port 8767
# Отдельное нативное окно и командный режим остаются доступны:
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --workspace "C:\путь\roi-workspace.json"
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --soc .24 --capacity .3 --speed 20
```

JSON скачивается кнопкой экспорта рабочего пространства на сайте. Выберите файл `roi-workspace.json`, содержащий границу, зоны, карту глубин и самосвал. Экспорт результатов `truck-test.json` имеет другой формат. Без файла запускается демонстрационный полигон. Данные на сайте не изменяются. Для нескольких самосвалов пока выбирается первый.

В браузере: перетаскивание мышью вращает сцену в инвертированном направлении, колесо меняет масштаб. Контекстное меню и выделение на сцене отключены. Кнопки «За самосвалом» и «Общий вид» переключают камеру. Пауза, остановка и сброс находятся в верхней панели. Для своих проектов войдите в аккаунт; браузерное хранилище localhost отдельно от GitHub Pages. В нативном окне: **F** включает слежение, **пробел** — паузу, **R** — сброс; панели MuJoCo скрываются Tab / Shift+Tab. Голубая линия — активный рабочий путь, жёлтая — путь к зарядке, розовая — возвращение после зарядки. Красные блоки — препятствия; цвета пола показывают высоту. Цвета границ: голубая транспортная область, оранжевая добыча, сиреневый склад, зелёная зарядка.

Рабочий цикл бесконечный: добыча → погрузка 4 с → склад → разгрузка 4 с → добыча. При снижении заряда машина тормозит, строит новый путь от фактической позиции, подъезжает к станции, совмещается с ней и заряжается. После отключения с грузом едет на склад, без груза на добычу. Для путей используется тот же JavaScript-планировщик глубин, границ, арукомаркеров и корпуса станции, что на сайте. Текущие приоритеты планировщика: минимальный максимальный перепад, сумма перепадов, длина.

## Что моделируется

Это тестовый стенд, а не цифровой двойник изготовленного устройства. MuJoCo интегрирует динамику шасси x/y/z/yaw/pitch/roll, контакты с полем высот, препятствиями и станцией, шарнир кузова и три приводные оси станции. Координаты машины после запуска не перезаписываются. Шесть опорных сфер и стабилизаторы наклона приближённо заменяют опорную поверхность гусениц; продольная сила и боковое сопротивление задаются контроллером с компенсацией уклона. Это не модель отдельных траков, подвески, деформации грунта или достоверного опрокидывания.

Для 3D создаётся отдельное поле высот `elevation`, единица `m`. Старые условные глубины не переименовываются в метры: из них сохраняются запрещённые клетки, а синтетическая высота рассчитывается отдельно. На поле 10×7 м номинальный перепад по умолчанию 0,75 м, фактический диапазон демонстрации примерно 0,11–0,64 м. Поверхность плавная, рабочие площадки выровнены, между ними плавные переходы. В параметрах доступны перепад 0–1,5 м и допустимый уклон 2–25° (по умолчанию 18°). В планировщик передаются метрические высоты, препятствия расширяются на 120 мм для габарита машины. Числа на панели показывают высоту поверхности от условного нуля, а не абсолютную геодезическую отметку; отдельно отображаются наклоны шасси. Карта является физическим MuJoCo heightfield, по которому движутся опоры. JSON расчёта содержит единицы, диапазон и текущую высоту. Препятствия возвышаются на 160 мм над поверхностью. Масса шасси при погрузке не пересчитывается, груз влияет на расчёт управляющей силы. Рабочие зоны не имеют силовых стенок; соблюдение границ обеспечивает планировщик.

Все размеры техники условные. Скорость 0,09 м/с, колея 110 мм и станция 300×200 мм взяты из тестовой конфигурации сайта, а не из подтверждённого CAD. Перемещение контакта станции 160 мм, высота 80 мм. Электрическая модель — упрощённая батарея 1S, внутреннее сопротивление 0,12 Ом и заряд CC/CV до 90 %: в браузере расчёт выполняет существующая JavaScript-модель, в нативном режиме — Python; это не электрический решатель MuJoCo. Заряд разрешён только после совмещения и выдвижения механизма, при потере положения ток отключается. Контакт проверяется геометрически, усилие разъёма не моделируется. Параметры реального JGA25-370 и батареи ещё требуют идентификации.

## Проверка без окна

```powershell
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\test_simulation.py
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --headless --seconds 500 --output test-output\mujoco.json
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --headless --seconds 1 --screenshot test-output\mujoco.png
# При запущенном локальном интерфейсе:
node test_mujoco.cjs
# Проверка публичной WASM-версии без Python (после npm run build):
node test_web3d.cjs
```

`--seconds` ограничивает модельное время; без него работа в окне продолжается до закрытия. `--speed` ускоряет воспроизведение, сохраняя длительности в модельных секундах. `--soc` — начальный заряд от 0,1 до 0,95; `--capacity` — тестовая ёмкость от 0,1 до 5 А·ч. Результат JSON содержит историю состояний и явную отметку `synthetic`.

Python API и окно: [официальная документация MuJoCo](https://mujoco.readthedocs.io/en/stable/python.html).
