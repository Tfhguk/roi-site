# 3D симуляция MuJoCo

На сайте кнопка **«3D симуляция»** открывает `truck.html`: официальный MuJoCo WebAssembly рассчитывает физику в Web Worker, Three.js рисует интерактивную сцену через WebGL. Это работает непосредственно на GitHub Pages, без Python и собственного сервера. Первая загрузка включает примерно 11 МБ WASM до сжатия. Выбор проекта, техники, маршрута, параметры, телеметрия и экспорт используют существующий интерфейс; исходные проекты в базе не меняются.

Локальный запуск из корня проекта: **`start-mujoco.cmd`**, адрес `http://127.0.0.1:8766/truck.html`. Лаунчер также подготавливает Python-окружение для дополнительного нативного режима; нужны Python 3.10+ и Node.js в PATH. Старый режим с Python API и потоком изображений доступен явно по `truck.html?mujoco=1`, а 2D версия — по `truck.html?view=2d`. Для обычной работы на сайте эти режимы не нужны.

Граф маршрутов готовится один раз; сброс с теми же параметрами переиспользует скомпилированную модель и GPU-сцену. Физика передаёт только преобразования движущихся объектов, статичные препятствия рисуются одним набором экземпляров. Камера вращается сразу в браузере, без сетевых запросов; неизменившаяся сцена не перерисовывается.

В браузерной 3D версии застревание определяется по фактическому перемещению и повороту шасси за 3 модельные секунды. Машина делает до двух попыток безопасно отъехать и построить объезд; неудачный подход исключается из автоматического планирования. Если выехать не удалось, открывается запрос оператора. Кнопка «Взять управление» включает стрелки/WASD и экранные кнопки; ручной режим работает при ×1, отпускание кнопок и потеря фокуса тормозят машину. Команда движения истекает через 350 мс без обновления. Ручное управление не применяет ограничения планировщика по уклонам, клеткам глубины и прошлым застреваниям: на склоны можно заезжать и съезжать, действует физика поля высот и видимого корпуса станции. Программно сохраняется только внешняя граница полигона. «Вернуться к маршруту» строит путь от фактического положения к прежней цели, сохраняя груз, заряд и направление рейса. На зарядке и с поднятым кузовом ручное движение недоступно. Это управление тестовой моделью в браузере, без подключения к реальной технике.

Успешные проезды и проблемные участки сохраняются в браузере отдельно по аккаунту, полигону, машине и конфигурации рельефа. Память ограничена 20 путями и 20 проблемными участками для каждого из последних восьми наборов параметров. При повторном использовании путь заново проверяется: память не отменяет проходимость. При сбросе опыт сохраняется; «Забыть опыт» в окне анализа очищает его после остановки. Общие проекты в Supabase не изменяются, между устройствами память не синхронизируется. JSON расчёта содержит опыт и оценку маршрута.

«Сброс» возвращает машину к началу выбранной траектории внутри полигона, обнуляет время, груз, рейсы и восстанавливает начальный заряд. Начальная позиция хранится в положении тела шасси, а координаты его скользящих суставов — как относительные смещения. Поэтому стандартный сброс MuJoCo тоже сохраняет машину внутри полигона. Ответы от старого расчёта после сброса не применяются к новому.

```powershell
.\start-mujoco.cmd
.\start-mujoco.cmd --port 8767
# Отдельное нативное окно и командный режим остаются доступны:
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --workspace "C:\путь\roi-workspace.json"
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --soc .24 --capacity .3 --speed 20
```

JSON скачивается кнопкой экспорта рабочего пространства на сайте. Выберите файл `roi-workspace.json`, содержащий границу, зоны, карту глубин и самосвал. Экспорт результатов `truck-test.json` имеет другой формат. Без файла запускается демонстрационный полигон. Данные на сайте не изменяются. Для нескольких самосвалов пока выбирается первый.

В браузере: перетаскивание мышью вращает сцену в инвертированном направлении, колесо меняет масштаб. Контекстное меню и выделение на сцене отключены. Кнопки «За самосвалом» и «Общий вид» переключают камеру. Пауза, остановка и сброс находятся в верхней панели. Для своих проектов войдите в аккаунт; браузерное хранилище localhost отдельно от GitHub Pages. В нативном окне: **F** включает слежение, **пробел** — паузу, **R** — сброс; панели MuJoCo скрываются Tab / Shift+Tab. Голубая линия — активный рабочий путь, жёлтая — путь к зарядке, розовая — возвращение после зарядки. Красные отметки — исключения для планировщика без физических стен; цвета пола показывают высоту. Цвета границ: голубая транспортная область, оранжевая добыча, сиреневый склад, зелёная зарядка.

Рабочий цикл бесконечный: добыча → погрузка 4 с → склад → разгрузка 4 с → добыча. Сначала планировщик ищет путь в предпочтительном диапазоне уклонов (по умолчанию до 18°). Если такого пути нет, допускаются более крутые участки до предельного угла (по умолчанию 25°, настройка до 30°), с проверкой габарита 200×150 мм, запаса тяги с полным грузом и поперечного наклона. Для тяги требуется запас не менее 10 %. Оценка использует синтетические параметры; прохождение проверяет физическая модель. При снижении заряда машина тормозит и строит кратчайший допустимый путь к достижимой станции в выбранном диапазоне уклонов. После зарядки с грузом едет на склад, без груза на добычу. Рабочие пути сохраняют приоритеты плавности рельефа; зарядные — длины пути. В окне «Проходимость и память» видны уклон, расчётный запас тяги и применение крутого участка или сохранённого пути.

## Что моделируется

Это тестовый стенд, а не цифровой двойник изготовленного устройства. MuJoCo интегрирует динамику шасси x/y/z/yaw/pitch/roll, контакты с полем высот, препятствиями и станцией, шарнир кузова и три приводные оси станции. Координаты машины после запуска не перезаписываются. Шесть опорных сфер и стабилизаторы наклона приближённо заменяют опорную поверхность гусениц; продольная сила и боковое сопротивление задаются контроллером с компенсацией уклона. Это не модель отдельных траков, подвески, деформации грунта или достоверного опрокидывания.

Для 3D создаётся отдельное поле высот `elevation`, единица `m`. Старые условные глубины не переименовываются в метры: из них сохраняются запреты для автопилота, а синтетическая высота рассчитывается отдельно. На поле 10×7 м номинальный перепад по умолчанию 0,75 м, фактический диапазон демонстрации примерно 0,11–0,64 м. Поверхность плавная, рабочие площадки выровнены, между ними плавные переходы. Перепад регулируется от 0 до 1,5 м. Красные отметки запрещённых клеток рисуются поверх рельефа: они не являются коллизионными блоками и не удерживают машину при ручной езде. Расширение запретов на 120 мм и запас у станции существуют только в планировщике. Физические контакты есть с самим полем высот и реальной геометрией станции. Числа на панели показывают высоту поверхности от условного нуля и наклоны шасси. Масса шасси при погрузке не пересчитывается, груз влияет на расчёт управляющей силы.

Все размеры техники условные. Скорость 0,09 м/с, колея 110 мм и станция 300×200 мм взяты из тестовой конфигурации сайта, а не из подтверждённого CAD. Перемещение контакта станции 160 мм, высота 80 мм. Электрическая модель — упрощённая батарея 1S, внутреннее сопротивление 0,12 Ом и заряд CC/CV до 90 %: в браузере расчёт выполняет существующая JavaScript-модель, в нативном режиме — Python; это не электрический решатель MuJoCo. Заряд разрешён только после совмещения и выдвижения механизма, при потере положения ток отключается. Контакт проверяется геометрически, усилие разъёма не моделируется. Параметры реального JGA25-370 и батареи ещё требуют идентификации.

## Проверка без окна

```powershell
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\test_simulation.py
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --headless --seconds 500 --output test-output\mujoco.json
.lan-tls\mujoco-venv\Scripts\python.exe mujoco_sim\simulate.py --headless --seconds 1 --screenshot test-output\mujoco.png
# При запущенном локальном интерфейсе:
node test_mujoco.cjs
# Проверка публичной WASM-версии без Python (после npm run build):
node test_web3d.cjs
node test_recovery.cjs
node test_learning.cjs
node test_traction.cjs
```

`--seconds` ограничивает модельное время; без него работа в окне продолжается до закрытия. `--speed` ускоряет воспроизведение, сохраняя длительности в модельных секундах. `--soc` — начальный заряд от 0,1 до 0,95; `--capacity` — тестовая ёмкость от 0,1 до 5 А·ч. Результат JSON содержит историю состояний и явную отметку `synthetic`.

Python API и окно: [официальная документация MuJoCo](https://mujoco.readthedocs.io/en/stable/python.html).
