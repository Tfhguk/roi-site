# Подключение GUI к AR — предлагаемый контракт v1

Реализован браузерный клиент `ar.html`, а не сервер измерения поверхности. Основа — переданный `GUI_API.md`. Форматы **ответов** ниже дополняют исходный проект контракта и требуют согласования с разработчиком AR. Демо не обращается к оборудованию и не выдаёт данные за измеренные.

## Запуск и границы этапа

На главном экране есть «AR / Проектор». Без сервера нажмите «Демо». Для реального подключения укажите базовый адрес, например `http://127.0.0.1:8765`, и нажмите «Подключиться». Автоматического подключения и автоматической отправки настроек при загрузке страницы нет.

Сайт опрашивает состояние раз в секунду, последовательно. JPEG запрашивается при изменении номера снимка или ревизии изображения. При ошибке состояния повторный опрос — через 3 с. Тайм-аут запроса — 5 с. Старое изображение сохраняется с обозначением потери связи; изменение установки блокируется до восстановления соединения.

Есть прямоугольник, простой вогнутый/выпуклый полигон, перетаскивание, добавление вершины на ребре, удаление, отмена и замыкание правой кнопкой мыши. 3–32 вершины без повторов и самопересечений. Координаты относятся ко **всему** изображению проектора; меньшая область не растягивается. Доступный прямоугольник поступает от AR; 1280×800 и `[227,0,1053,800]` используются только в демо.

Черновики хранятся в localStorage данного браузера отдельно для адреса установки. Замкнутый корректный черновик восстанавливается только при совпадении ревизии, размеров и доступного поля. Восстановление не отправляет настройки. Изменившаяся привязка требует подтверждения. «Взять настройки AR» заменяет черновик серверными значениями. Общие пресеты Supabase и гаражи не изменяются.

## `GET /api/v1/state`

```json
{
  "schema_version": 1,
  "stage": "ready",
  "projection_revision": "projector-17",
  "projection": {
    "width": 1280,
    "height": 800,
    "available_rect": [227, 0, 1053, 800],
    "calibration_3d_accepted": true
  },
  "settings_revision": "settings-4",
  "settings": {
    "schema_version": 1,
    "height_range_m": [0, 0.5],
    "above_range": "black",
    "palette_gamma": 0.5,
    "update_interval_s": 1,
    "roi": {
      "coordinate_space": "projector_normalized",
      "vertices": [[0.25, 0.15], [0.75, 0.15], [0.75, 0.85], [0.25, 0.85]]
    }
  },
  "snapshot": {
    "id": 42,
    "age_s": 0.3,
    "projection_revision": "projector-17",
    "settings_revision": "settings-4"
  },
  "metrics": {
    "check_hz": 1,
    "update_count": 42,
    "measured_fraction": 0.94,
    "filled_fraction": 0.04
  },
  "errors": []
}
```

`stage`: `mount_pending`, `stereo_required`, `floor_required`, `projector_required`, `ready`. До калибровки `projection`, `settings`, `snapshot` могут отсутствовать. Для `ready` обязательны поле, текущие настройки и принятая 3D-калибровка. Монтаж и стерео/проекторная калибровка выполняются в программе AR.

`available_rect` — `[left, top, right, bottom]`, координаты границ пиксельного поля. Ревизии — непустые строки либо неотрицательные целые; при сравнении GUI приводит их к строке. Изменение калибровки, разрешения или доступного поля должно менять `projection_revision`. Текущая серверная маска должна соответствовать текущему полю; иначе AR не должен объявлять готовую проекцию.

Неподвижная поверхность не требует новых снимков. `age_s` растёт, но удержание кадра при исправном опросе состояния само по себе не означает потерю связи. Если меняется только отображение, номер исходного снимка может сохраниться, а `snapshot.settings_revision` должен измениться после повторного построения проекции.

## `GET /api/v1/preview.jpg`

JPEG **полного** выходного изображения без элементов GUI. Размеры совпадают с `projection.width/height`. Пространство вне маски чёрное. Поверхности выше диапазона тоже чёрные и продолжают перекрывать свет; закрашивать их заполнением пропусков нельзя.

Обязательные заголовки привязывают байты JPEG к состоянию:

```http
Content-Type: image/jpeg
Cache-Control: no-store
X-Snapshot-Id: 42
X-Projection-Revision: projector-17
X-Settings-Revision: settings-4
```

Метаданные и JPEG формируются согласованно. GUI отвергает кадр с другой ревизией, номером или размером. При гонке между запросами новое состояние читается при следующем опросе. При частом обновлении серверу желательно удерживать кадр достаточно долго для двух запросов; будущий API может добавить получение конкретного номера снимка.

## `POST /api/v1/settings`

```json
{
  "schema_version": 1,
  "request_id": "uuid-from-gui",
  "projection_revision": "projector-17",
  "expected_settings_revision": "settings-4",
  "height_range_m": [0, 0.5],
  "above_range": "black",
  "palette_gamma": 0.5,
  "update_interval_s": 1,
  "roi": {
    "coordinate_space": "projector_normalized",
    "vertices": [[0.25, 0.15], [0.75, 0.15], [0.75, 0.85], [0.25, 0.85]]
  }
}
```

Предлагаемые пределы GUI: `0 ≤ min < max ≤ 0.5` м, гамма `0.1–3`, интервал `0.5–10` с, `above_range` только `black`. Сервер повторяет валидацию. Весь набор применяется атомарно; при ошибке прежние настройки сохраняются целиком.

Успех `200`:

```json
{"request_id":"uuid-from-gui","settings_revision":"settings-5","snapshot_id":42}
```

Сервер повторно отображает последний снимок и публикует JPEG с новой `X-Settings-Revision` даже при неподвижной сцене. GUI ожидает подтверждённый кадр, а не объявляет готовность по одному POST. Через 10 с без подтверждения появляется уведомление; автоматической повторной отправки нет.

Ошибка `400/422`:

```json
{"request_id":"uuid-from-gui","error":{"field":"roi","message":"Маска пересекает себя"}}
```

Устаревшая `projection_revision` или `expected_settings_revision` — `409` без изменения настроек. `expected_settings_revision` — предлагаемое расширение против перезаписи параллельных изменений. Отсутствие согласованного ответа не доказывает, что POST не был применён: GUI предлагает проверить состояние. Серверу следует обеспечивать идемпотентность по `request_id`.

## Действия

`POST /api/v1/actions/rescan` и `POST /api/v1/actions/calibrate-floor`:

```json
{"schema_version":1,"request_id":"uuid-from-gui","projection_revision":"projector-17"}
```

Ответ `200/202`:

```json
{"request_id":"uuid-from-gui","accepted":true,"action_id":"operation-12"}
```

Это подтверждение начала, не завершения. Дальнейшие стадии и ошибки поступают через `state`. Перед калибровкой пола GUI просит освободить поверхность. Применение/пересканирование доступны только при готовой установке. После смены калибровки меняется ревизия; старая маска автоматически не отправляется.

## Размещение и доступ

Для другого origin сервер обрабатывает `OPTIONS`, разрешает согласованный origin сайта, методы `GET, POST, OPTIONS` и `Content-Type`. Для метаданных JPEG нужен:

```http
Access-Control-Expose-Headers: X-Snapshot-Id, X-Projection-Revision, X-Settings-Revision
```

Клиент не передаёт cookies Supabase или токены аккаунта на адрес AR. Разрешённые origin, HTTPS/доверие сертификату, доступ браузера к локальному оборудованию и авторизацию самого AR нужно согласовать при размещении сервера. Клиент не обходит ограничения браузера и не открывает локальную установку в интернет. Одновременных операторов должен контролировать AR-сервер.

## Следующий этап

Числовой карты высот и положения техники здесь пока нет. Для MuJoCo/маршрутов нужны сетка в метрах, физические X/Y, оси/масштаб, время и ревизия измерения, маска валидности и признаки измеренных/восстановленных ячеек. Чёрный пиксель проекции нельзя считать препятствием или отсутствующей высотой. Связь проектора, мира и камеры/арукомаркеров следует калибровке, а не растяжению 1000×700 в 1280×800.

Проверка без оборудования: `node test_ar.cjs` после `npm run build`. Проверяются демо, HTTP-клиент, ошибки полей, ревизии, кадры, ручная отправка и адаптивная вёрстка.
